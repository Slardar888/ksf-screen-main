## 一、版面：原坐标 100% 保留 + 等比网格实现

这是本项目的**第一原则**：原站每个元素的位置都是实测来的，
**所有文字、按钮、数字的版面位置不得改动**。

实现方式（`src/components/hmi/primitives.tsx`）：

| 目标 | 做法 |
| --- | --- |
| 保留原坐标 | 所有图元**沿用原来的 `x` / `y` / `w` / `h` 入参**，与改造前的页面源码逐一对应 |
| 不用绝对定位 | 把「绝对像素坐标」换成「按原坐标落到等比网格轨道」：`Stage` 是一个铺满视口的 CSS Grid |
| 位置精度 | 网格粒度 `GRID_STEP = 2`（原设计稿 px），位置误差 ≤ 1 设计 px |
| 铺满全屏 | `.hmi-stage` 高度 `100dvh`，无黑边、无 letterbox |
| 自适应 | 网格轨道用 `1fr`，随视口等比缩放；字号用容器查询单位 |

```tsx
// 页面写法与改造前完全一致，只是不再有绝对定位
<Stage width={1280} height={800}>
  <Panel x={10} y={122} w={461} h={62} />
  <Text x={10} y={122} w={230} h={62} size={35} plate>速度设置：</Text>
  <Readout x={240} y={122} w={230} h={62} value={state.speedSet} size={50} digits={1} />
  <ArrowButton x={963} y={181} w={154} h={92} direction="up" onClick={…} />
</Stage>
```

### 嵌套语义

`Abs` / `Panel` / `DarkPanel` 会为自己建立一个**同尺寸的子网格**，
其内部子元素继续用**相对该容器**的 `x / y / w / h` ——
与原实现中「绝对定位建立 containing block」的行为一致
（例：`SystemAdminPage` 的多行标签 `<Abs><Text x={0} y={i*38}></Abs>`）。

两个已经踩到的坑（已在图元层统一处理）：

1. **子网格里的裸内容会塌缩**。`<Abs>` 内的裸 `<div>` / `<svg>` / `<input>` 若不带
   定位信息，会被自动放进第一个网格单元，塌成 2px 见方。
   已用 `.hmi-subgrid > :not([data-box]) { grid-area: 1 / 1 / -1 / -1 }` 全局修正。
2. **超出画布边界的元素**。原设计稿里有少数元素略微越界
   （如 `y=690 + h=120 > 800`），原实现由 `Stage` 的 `overflow: hidden` 裁掉，
   现在行为一致。

所有令牌定义在 `src/index.css` 的 `:root`，单位是「原设计稿 px」，经 `--u` 换算成当前视口尺寸。

| 规范项 | 值 | 强制方式 |
| --- | --- | --- |
| **按钮文字** | `SPEC.btn = 28`（全站唯一） | `HmiButton` 忽略页面传入的 `size`，一律用该档 |
| **主菜单大磁贴文字** | `SPEC.tile = 50`（单独一档） | 磁贴尺寸 384×189，用 28 会明显偏小（原稿即为 50）；传 `big` 启用 |
| **输入框文字** | `--fs-input: 34`（全站唯一） | `NumberField` / `Stepper` 一律用该令牌 |
| **输入控件高度** | `--ctl-h: 56`（全站唯一） | 控件外框 `.hmi-ctl` 固定高度，在原始盒子里垂直居中 |
| **文字字号阶梯** | `20 / 25 / 30 / 35 / 40 / 44 / 50 / 80` | `Text` 把传入的 `size` 归一到最近一级 |
| **数值读数** | 固定 44（`--fs-num`） | `Readout` 忽略页面传入的 `size` |
| **页面标题** | `SPEC.title = 50`（全站唯一） | 统一标题条组件 `PageHeader`；两行式顶栏 `ScreenHeader` 的标题行也套用同一规范 |
| **标题条高度** | `SPEC.titleBarH = 56` | 同上 |
| **内边距** | 标签 12 / 普通文字 8（`--pad-ctl` / `--pad-inner`） | 图元自动加 `padding-inline`，文字不贴边 |
| **对齐网格** | 4 设计稿 px（`--align`） | `place()` 把左右、上下两条边分别吸附，相邻元素共享对齐线 |

### 文字完整显示的兜底策略（第 3 点）

`useFitText()` 按**三级策略**处理文字放不下的情况，优先保「内容完整」，其次保「字号规整」：

1. 规范档位 + 规范内边距 —— 能放下就用（绝大多数情况，全站字号因此始终落在 8 档内）；
2. 仍放不下 → 牺牲内边距（改为 0）保住档位；
3. 极少数盒子实在太小（如 6 个汉字塞在 123px 宽的格子里）→ 才等比缩小；
   这类盒子本轮已用**加宽内容框**的方式修掉，因此实际未触发第 3 级。

判据同时包含**横向**（`scrollWidth` 扣掉内边距）与**纵向**（字号不得高于盒高，
因为网格吸附会把盒高压掉 1~2px）。

### 标题统一（全站）

原稿的标题实现有 **5 种**、字号从 30 到 80 不等、位置从 y=0 到 y=81 不等。
现在统一为一个组件 `PageHeader`：

```tsx
<Stage width={1280} height={800}>
  <PageHeader title="预置计数" width={1280} />
  …
</Stage>
```

它统一了：**底条高度、标题字号、水平居中、`.hmi-page-title` 样式**
（字重 700 / 白字 / 青色辉光 / 字距 0.06em）、右上角时钟位置与字号。

#### 为什么标题必须用 `--ut` 而不是 `--u`

各页画布尺寸不同（1280×800 与 1920×1080 两种）。`--u = min(视口宽/画布宽, 视口高/画布高)`
是**跟着画布走的**，所以同一个"50"在不同画布上渲染出的像素并不相同 ——
在 1920×1080 视口下，1280×800 页面渲染成 **67.5px**，1920×1080 页面渲染成 **50px**，
看起来就是"各页标题大小不一"。

因此标题条改用 `--ut`（**页面外框单位**，永远以 1280×800 为基准，与画布无关）：

```css
--ut: min(calc(100cqw / 1280), calc(100cqh / 800));   /* 每页同值 */
```

标题条的高度与字号全部走 `--ut`，于是不论画布多大，**所有页面的标题渲染出来完全一致**：

| 视口 | 标题实际字号 | 标题底条实际高度 | 居中偏差 |
| --- | --- | --- | --- |
| 1920×1080 | **50px**（13 页全部相同） | 76px | 0px |
| 1366×768 | 35.5px（13 页全部相同） | 54px | 0px |

字号与底条高度由 `SPEC.title` / `SPEC.titleBarH` 单点持有，`<Stage>` 注入为
`--title-size` / `--titlebar-h`（当前 37 / 56，即 1920×1080 下渲染 50px / 76px），
改一处即全站生效。

**逐页放大**：`PageHeader` 支持 `titleSize` / `barHeight` 两个可选覆盖参数，
实现上只是把这两个**数据**覆盖到标题条自身，Tailwind 类名完全不变。
目前只有主菜单使用（它画布 1920×1080、磁贴 384×188，比其它页大一号）：

```tsx
{/* 其余 13 页不传，沿用全站统一值 */}
<PageHeader title="主菜单" width={1920} titleSize={48} barHeight={72} />
```

| 页面 | 标题实际字号 @1920 | 底条实际高度 |
| --- | --- | --- |
| 主菜单 | **64.8px** | 97px |
| 其余 13 页 | 50px | 76px |

标题用 `grid-template-columns: 1fr auto 1fr` 做三栏布局，左右两栏等宽，
因此标题落在**画面正中央**（而不是"扣除时钟后的剩余区域中心"）。

| 页面类型 | 标题所在 |
| --- | --- |
| 单行标题页（主菜单 / 预置计数 / 接头检测 / 料泵清洗 / 角度监控 / 超级用户 / 系统管理员 / 管制卡 / MES / I-O） | `PageHeader`，标题行 y=0 |
| 两行式顶栏页（操作画面 / 参数设置 / 温度设定） | `ScreenHeader`，第一行工单信息 y=0，标题行 y=61 |

两类的标题样式完全一致，差别只是后者多一行工单信息。
`PlainTitle` 已废弃，不要再使用。

### 逐页版面整理

在规范令牌之外，部分页面还需要**逐页**调整版面的对齐与节奏。已完成：

#### 操作画面（`OperationScreenPage.tsx`）

| 问题 | 处理 |
| --- | --- |
| 计数行标签块比其它行宽 10px（240 vs 230） | 标签列统一 `x=10 / w=230` |
| 计数行数值左对齐、右侧大片留白 | 数值区 240–683 内**居中**；各行数值居中偏差实测 0 |
| 输入控件比所在行偏下（Stepper `y+2`、NumberField `y+10`） | 控件盒子与所在行同高同起点，实测垂直偏差 **0** |
| 各行间距不等（20/21/17/26…） | 统一节奏：行高 64、行距 20、步长 84 |
| 右列间距不等（11/23/12/21/13） | 与左列共用 20 间距 |
| 底部动作条间距 101/102/61/19 | 5 个按钮同宽 192、间距统一 72 |

**关键坑**：节奏常数**必须取 4 的倍数**。图元会把每条边吸附到 4px 对齐网格，
若步长取 82（非 4 的倍数），吸附后行距会在 18/22 之间交替，看上去依然"不相等"；
同理，同为 197 宽的按钮在不同起点会被吸附成 196 或 200，导致间距变成 72/68/68/72。
把步长、宽高、起点全部取 4 的倍数后，实测间距才真正相等。

## 三之三、样式：全部用 Tailwind className 表达

本项目**没有手写 CSS**。`src/index.css` 只剩两样东西，共 57 行：

```css
@import "tailwindcss";

@theme {
  --font-ui:   …;   /* 中文无衬线栈 */
  --font-tech: …;   /* 数字工业感等宽栈 */
  --color-hmi-*: …; /* 全部颜色令牌 */
  --radius-card: 14px;
  --radius-ctl: 10px;
}
```

`@theme` 是 Tailwind 自身的配置机制（用来生成 `font-ui` / `text-hmi-cyan` /
`rounded-card` 等工具类），除此之外**零自定义规则** —— 没有 `@layer components`，
没有 `.hmi-*` 类。构建产物里 `.hmi-` 自定义类数量为 **0**。

### 样式写在哪

所有组件样式是 Tailwind 类字符串，集中在 **`src/components/hmi/styles.ts`**：

```ts
export const BTN = "… rounded-md border border-[rgba(96,166,255,0.42)] … hover:brightness-[1.14] …";
export const CTL = "… h-[calc(var(--u)*56)] px-[calc(var(--u)*12)] …";
export const TONE = { live: "text-hmi-live", set: "text-hmi-set", … };
```

图元与页面只引用这些常量；要改外观，改这一个文件即可全站生效。

**关键约束**：类名必须是**完整字面量**，不能拼接字符串 ——
否则 Tailwind 扫描不到、不会生成对应 CSS。所以凡是依赖画布缩放单位 `--u` 的尺寸，
都写成 `h-[calc(var(--u)*56)]` 这样的完整字面量，而不是 `` `h-[calc(var(--u)*${N})]` ``。

### 三类「不是样式」的东西仍然保留

| 类别 | 位置 | 为什么不能用 className |
| --- | --- | --- |
| **画布几何** | 图元的 `style={{ gridColumn, gridRow }}` | 行/列线号由元素坐标在运行时算出，Tailwind 无法静态识别；这是**布局数据**，不是样式 |
| **缩放单位** | `<Stage style={{ "--u": …, "--ut": …, "--title-size": … }}>` | 自定义属性是**数据传递**（设计稿 px → 视口像素的换算基准），由 `calc(var(--u) * N)` 消费 |
| **@theme 令牌** | `index.css` | Tailwind 的配置入口，用来生成工具类 |

### 测试钩子与样式解耦

四个审计脚本不再依赖类名（类名随时可改），改用 `data-*` 属性定位元素：
`data-canvas` / `data-box` / `data-titlebar` / `data-page-title` / `data-btn` /
`data-btn-tier` / `data-ctl` / `data-value` / `data-arrow` / `data-text`。
这样**样式怎么改都不会让回归测试失效**。

### 组件约定：`data-node-id` 一律透传到 render 的第一个 DOM 元素

`vite.config.ts` 启用了 `@kesi/vite-plugin` 的 `enableNodeIds`。**开发模式下**该插件
给 `src/pages` 下每个 JSX 元素注入

```
data-node-id = "node-" + base64url({ file, startLine, startCol, endLine, endCol })
```

工具拿它调 `GET /__editor/node/{id}` 就能定位源码（生产构建不受影响）。
插件在 `dist` 里的规则是：

```js
const hasId = open.attributes.some(a => a.name?.name === 'data-node-id');
if (hasId) return;                       // 元素已经声明了 → 跳过
open.attributes.push({ … value: id });   // 否则**追加到属性列表最后**
```

于是有两条必须遵守的规矩：

#### 规矩 1：hmi 图元要把传入的 `data-node-id` 透传到第一个 DOM 元素

页面里的元素绝大多数是**自定义组件**（`<Text>` / `<Panel>` / `<HmiButton>` …），
`data-node-id` 是当 prop 传进去的，React 不会自动落到 DOM 上 —— 不透传这条 id 就丢了。
做法：props 类型并上 `Passthrough`，把 `...rest` 展开到**第一个 DOM 元素**上。

| 图元 | 属性最终落在 |
| --- | --- |
| `Stage` / `Abs` / `Box` / `Text` / `Readout` / `NumberField` / `Stepper` / `Panel` / `DarkPanel` / `PageHeader` / `VerifyPasswordDialog` | 各自的根 `<div>` |
| `HmiButton` / `StatusButton` / `ArrowButton` / `TouchButton` / `NavPair` / `OperationButton` | 第一个 `<button>` |
| `SealUnitGraphic` | `<svg>` |
| `Clock` | 转发给内部 `Text` 的 `<div>` |
| `ScreenHeader` | 第一条 `<Panel>`（render 出多个根节点） |
| `FitBox` | 同 `Stage`（本身就是 `export const FitBox = Stage`） |

`Passthrough` 排除了 `className` / `style` / `children`（图元内部要拼装）与
`onClick` / `onChange`（与图元自身同名 prop 求交会把 `(v: number) => void` 判成类型错误），
另外**显式声明了 `"data-node-id"?: string`**，因为渲染时要把它单独取出来（见规矩 2）。

#### 规矩 2：页面内部的局部组件要**显式声明** `data-node-id`，不能只靠 `{...rest}`

这是踩过的坑。页面里那些行/块组件（`Row` / `TempRow` / `Counter` / `Block` /
`TempChannel` / `AlBox` / `JogButton` / `ParamCell` / `Field` / `NumRow`）
定义在 `src/pages` 里，**它们内部的 JSX 也会被插件注入 id**，而且注入位置在属性列表最后：

```js
jsxDEV(Panel, { x, y, w, h, ...rest, "data-node-id": "node-<组件内部这个Panel>" })
//                                ↑ 调用点透传的          ↑ 插件注入的，在后面 → 把上面顶掉
```

所以只用 `{...rest}` 的话，**调用点的 id 永远被组件内部那个 id 顶掉**，点页面元素定位不到
`<Row y=… />` 那一行。修法是先把 id 取出来、再作为**显式属性**写回第一个根元素 ——
插件看到元素已声明 `data-node-id` 就跳过，调用点的 id 才能落到 DOM：

```tsx
function Row({ y, label, value, "data-node-id": nodeId, ...rest }: RowProps & Passthrough) {
  return (
    <>
      <Panel x={LABEL_X} y={y} w={461} h={ROW_H} {...rest} data-node-id={nodeId} />
      …
```

> 另一条路是把这些组件挪到 `src/pages` 之外（插件只转换 `pagesDir`，内部 JSX 就不会被
> 注入），那样 `{...rest}` 也不会被顶掉。代价是要把一套行几何常量一起搬走，
> 所以选了"显式写回 id"这条改动更小的路。两种做法都试过，结果都对。

配套地，这些 helper **必须是组件**（`<Row y={…} />`）而不是"返回 JSX 的函数"（`{row(…)}`）：
后者在调用点上根本没有元素可挂 id。

### `node-id.mjs` —— 两部分体检

```bash
node .workbuddy/node-id.mjs
```

**A. 逐图元**：打开仅开发环境注册的探针页 `/#/__nodeid-probe`
（`src/pages/__NodeIdProbe.tsx`），把 20 个图元各自放进一个独立容器并传入
`data-node-id="nid-图元名"`，断言属性落在**容器的第一个 DOM 元素**上，并打印落在哪种标签上。

**B. 真实页面**：对**全部 13 个画布页面**，把「插件注入到页面模块里的 node-id 集合」与
「浏览器 DOM 里实际出现的集合」做差集。例外只有两类，都是"没有 DOM 元素可承载属性"，
不是透传漏了：

| 例外 | 说明 |

### 关于审计里剩下的两类告警

两类都**不是本次改动引入的**，而是原设计稿固有的，已用实测数据确认：

1. **个别标签文字宽度超出其盒子**（如「计算：」字号 40 需 108px，原盒宽仅 82px）。
   中文全角字宽恒为 1em，原站用楷体也是同样宽度，因此原站同样会裁切。
   复现方式：按设计稿 1:1 换算后，实测文字宽 > 原盒宽。
   注：由于 `--u` 取宽高两个缩放比例的**较小值**，宽屏下文字相对盒宽反而更小，
   所以本实现裁切得**比原站更少**。
2. **少数控件触摸高度不足 44px**（如 MES 页 32px 高的下拉/输入框）。
   原设计稿本身就是 32px，1:1 时即低于 44px，属原站设计取舍。
   （注：本轮统一控件高度只作用于 `NumberField` / `Stepper`，MES/I-O 页使用的原生
   `input` / `select` 仍按原稿尺寸，以免改变这两个宽屏页的版面。）
